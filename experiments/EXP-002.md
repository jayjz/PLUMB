# EXP-002 — Source-informed scope verification infrastructure

**Date:** 2026-10-09. **State:** dataset/evaluator upgrade; **model experiment unrun**. Dataset `exp002-1.0.0-provisional`: 30 source-informed synthetic cases, 18 development / 12 held out, zero independently human-reviewed labels. No paid API calls, model performance estimates, customer results or product launch.

## Question and estimand

Does explicit scope extraction or a separately specified deterministic verification step improve issue detection and appropriate clarification over a **strong general-model direct baseline with exactly the same information**? The intervention is the checking procedure, not privileged source access, a weaker baseline, extra context or an undisclosed inference budget. Because all conditions receive source notes, this study cannot isolate the causal effect of access to sources. It also cannot test retrieval quality or field reliability.

Primary hypothesis: supported contradiction/omission/quantity detection improves without an unacceptable increase in unsupported warnings on clean/superseded cases. A null or worse result is useful evidence against further development. Do not redefine success around whichever secondary metric improves.

## Freeze and evaluation procedure

1. Complete an independent qualified human label/source audit; resolve disagreements without viewing condition outputs. The prepared six-case sample begins this process, but all 30 need review before full-benchmark validation claims.
2. Use only development cases for prompt, parser, C-rule or budget selection. Record every trial. Freeze actual prompts, model/version, seeds, budgets, scoring code commit, human-approved dataset version and primary/secondary analysis before opening the holdout. Current prompts are candidate protocol artifacts, not evidence of optimization or run readiness.
3. Reserve all 12 held-out cases for a single prospective comparison after design decisions are locked. Balance condition order across cases using a recorded seed; execute each independently. If repeating, use the same predeclared repeat count and paired seeds for all arms; do not selectively rerun failures. This draft defaults to one repeat and reports stochastic uncertainty as unmeasured.
4. Save manifests/inputs/raw outputs locally under ignored `runs/`. Bind each prediction to its input hash and each review to prediction + dataset root hashes. Record Git commit, Python version and source identities. There are no API integrations in this PR and none were invoked.
5. Deterministically validate schema, quotation pointers, uniqueness, completeness and item localization. Independently blinded human reviewers judge entailment, authorization and action correctness, including false-negative audits. Never use the tested model as unquestioned judge.
6. Report raw paired case outcomes, TP/FP/FN by type, exact denominators, invalid/missing/abstain rates, supported issue precision/recall, negative-case warning rates, clean clearance, and uncertainty clarification separately. Candidate localization is not semantic performance. Supersession false warnings are distinct from clean false warnings. Report cost/latency and total inference usage for all attempts.

## Causal and statistical limits

Primary paired outcome: supported detection of the six held-out contradiction/omission/quantity issues, alongside false warnings on four held-out negative controls. The two uncertainty cases are a separate secondary endpoint. Do not combine already acknowledged open questions with newly discovered proposal defects as a headline benefit. Raw case-level paired differences are more defensible than a percentage headline here. Case-level binomial intervals or McNemar calculations require independence assumptions that source-family clustering violates; if shown, label them exploratory. Only two held-out source clusters make cluster uncertainty estimates unstable; do not report narrow confidence or significance claims. Predeclare practical benefit/false-warning thresholds with domain reviewers before evaluation rather than choosing them after results. No monetary-value or generalization claim is supported by this small study.

Potential confounds include shared AI authorship, lexical approval cues, one issue per case, selected easy arithmetic, trade/source shift between partitions, equal source availability, lack of real errors/OCR, short context and underdetermined authority in practice. The strong baseline may already solve these tasks. Report that honestly rather than manufacturing advantage.

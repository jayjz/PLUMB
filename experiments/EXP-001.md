# EXP-001 — Pre-proposal scope assurance

**State:** Scaffolded / **unrun**. Date: 2026-10-09. Five entirely fictional exploratory cases. Not prospective statistical validation.

## Research question
Can a strong general-model direct prompt detect cross-document scope discrepancies, and does a structured extraction→comparison prompt or deterministic verification add value worth productizing?

## Hypothesis and falsifiers
H1: Structured source extraction improves consequential issue recall or reduces false warnings **when compared fairly** with direct prompting. Null: improvement absent or economically negligible. A negative result is a valid outcome.

## Dataset and ground truth
C001 approved framing material disagrees with proposal (**contradiction**).
C002 later documented authorized width revision is correctly included (**clean supersession**).
C003 client-approved rail material disagrees with proposal (**contradiction**).
C004 proposal omits agreed disposal of demolition debris (**omission**).
C005 scope and proposal align despite multiple observations (**clean**).

Gold labels were authored with these synthetic records, not independently adjudicated by an outside estimator. **Do not call them independently validated.** Inputs are in `data/cases/`; gold labels are in `data/gold/`. There are only three positive cases and two negative cases. Small counts are exploratory.

## Conditions
A: **Strong direct prompt**, all records in order, one-pass identification, JSON output.
B: **Structured prompt**, same records/context, extract authorized commitments and compare proposal, JSON output.
C: **Hybrid** (future; not scaffolded as an experimental condition), structured output plus deterministic checks only after pre-registering rule coverage.

Use the same model family/version, access to records, context budget, structured output constraints, retry limits and evaluation rules. Log tokens, cost, wall time, response errors. Freeze prompt and model metadata before runs. Each condition run independently, no gold in its context, no prompt tuning on these scored cases. Record repetition and pairing rules if expanding; model nondeterminism is possible.

## Outcomes
Primary: recall across three known positive issues, false warnings per clean case, precision. Secondary: valid citation pointers and qualitative review of whether cited text *actually supports* the claim, cost, latency and output validation failures. A confident wrong answer, unsupported citation or missed issue is a failure. Abstention/empty findings are allowed.

## Pilot steps
1. Validate inputs and scoring contract in CI (not a model evaluation).
2. Freeze `data/cases/`, `data/gold/`, prompts and version hashes.
3. Run A and B with an explicit model operator; save predictions + run manifest under ignored `runs/`.
4. Score with `python scripts/score.py --predictions runs/<file>.json`; inspect false positives and citation support by hand.
5. Document raw counts and failure cases. **Do not infer a 90% production rate from three positives.**
6. Proceed to 30+ independently reviewed, realistically sourced cases **only if** there is a plausible product advantage and candidate buyers.

## Gate
If strong direct prompting performs similarly to the structured alternative, stop or pivot rather than building generic proposal tooling. Offline scores cannot validate demand, field reliability, construction correctness or monetary value.

## Amendment discipline
Document any prompt/label/case edits in `docs/WORKLOG.md`; rerun only as development work and do not represent tuned cases as held out.
